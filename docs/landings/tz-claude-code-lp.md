# ТЗ для Claude Code: подставляющийся лендинг под Яндекс Директ

## 1. Что делаем

Один шаблон посадочной страницы для рекламы в Директе. Содержимое страницы зависит от адреса: из одного кода собираются три лендинга, а у лендинга B два варианта.

Лендинг D «До 6 млн» отменён (решение от 12.10.2026: бюджетный сегмент не целевой). Не делать его и не закладывать под него ничего в конфиге.

| Вариант | Адрес | Тексты (источник) |
|---|---|---|
| A · Подбор | `/lp/podbor` | `docs/landings/tz-a-podbor.md` |
| B · 1–2-комнатные | `/lp/kvartiry?type=1k`, `/lp/kvartiry?type=2k` | `docs/landings/tz-b-1-2-komnatnye.md` |
| C · С отделкой | `/lp/s-otdelkoy` | `docs/landings/tz-c-s-otdelkoy.md` |

Цель страницы одна: человек проходит квиз из четырёх вопросов, видит, сколько квартир нашлось, и оставляет телефон. Заявка уходит в Strapi, а Яне сразу приходит уведомление в Telegram.

**Тексты берутся из файлов `docs/landings/tz-*.md` дословно.** Не переписывать, не сокращать и не придумывать новые. Если для какого-то места текста нет, оставь `TODO` и сообщи об этом в отчёте.

**Вёрстка.** Макеты будут из Claude Design, их пришлю отдельно. До этого делай логику и каркас. Стили бери из токенов в разделе «Визуальный стиль» тех же ТЗ, ориентир — прототип https://claude.ai/artifact/B8FQnbMBpytVfdQ5SNuVEv.

## 3. Маршрут и рендер

- Страница `app/lp/[variant]/page.tsx`. Через `generateStaticParams` отдаём только три варианта, на любой другой — `notFound()`.
- **Подмена на сервере**, а не в браузере. H1 и остальные подменяемые тексты должны быть в HTML с первого байта: без мигания текста и чтобы модерация Директа видела тот же заголовок, что и в объявлении. Страница читает `searchParams` и поэтому рендерится на каждый запрос. Данные из CMS при этом кешируются как сейчас (`revalidate = 3600`).
- Параметр `type` для B принимается только из белого списка `1k | 2k`. Всё остальное, включая его отсутствие, даёт вариант по умолчанию «1–2-комнатные».
- **Сырые значения из адреса на страницу не выводятся никогда.** В том числе `utm_term` из Директа: по нему ничего не подставляем, он только уходит в заявку и в Метрику.
- На `/lp/*` нет шапки и подвала сайта, нет меню. Нет глобального `QuizPopup`: добавь `/lp` в его исключения рядом с `/quiz` (`quiz-popup.tsx:237`).
- `robots`: `noindex, follow` в metadata. Лендинги не должны попадать в sitemap. В `robots.txt` их **не** закрывать: робот Директа должен видеть страницу. Причина: у сайта уже проблемы с «малоценными» страницами в Яндексе, и почти дубли нам там не нужны.
- `title` и `description` в metadata берутся из конфига варианта.

## 4. Конфиг вариантов — `lib/landings.ts`

Один типизированный объект, единственный источник того, что отличается между лендингами. В компонентах не должно быть `if (variant === "s-otdelkoy")`, только чтение конфига.

```ts
interface LandingVariant {
  slug: "podbor" | "kvartiry" | "s-otdelkoy";
  label: string;                 // для заявки и Метрики: «C · с отделкой»
  meta: { title: string; description: string };
  hero: { h1: string; sub: string; cta: string };
  prices: { h2: string; cards: PriceCard[] };     // блок «Цены»
  extraFaq?: { q: string; a: string }[];          // добавляется к общим вопросам
  quiz: QuizQuestion[];                           // ровно 4 вопроса
  resultTitle: string;            // шаблон: «Нашли {n} {квартир} в {m} ЖК»
  bonus: string;                  // текст рамки «Пока ждёте»
  baseFilter: ApartmentFilter;    // что вообще может попасть в выдачу лендинга
  subvariants?: Record<string, Partial<LandingVariant>>; // B: { "1k": …, "2k": … }
}

interface PriceCard { title: string; filter: ApartmentFilter; }   // цена и платёж считаются из базы
interface QuizOption { label: string; filter?: ApartmentFilter; hint?: "fromPrice" }
interface QuizQuestion { key: string; title: string; options: QuizOption[] }

interface ApartmentFilter {
  types?: ("студия" | "1к" | "2к" | "3к" | "4к" | "5к")[];
  priceMin?: number; priceMax?: number;
  districts?: string[];           // slug из lib/districts.ts
  finish?: "clean" | "preclean" | "any";
  delivery?: "handed" | "withinYear" | "any";
}
```

Общие блоки одинаковы для всех вариантов: боль, «под ключ», преимущества, доверие, FAQ, финальный призыв, подвал. Их тексты лежат в одном месте, а не копируются в каждый вариант.

Вопросы квиза и варианты ответов берутся из раздела «Квиз» каждого ТЗ. Как ответы переводятся в фильтр:

| Ответ | Фильтр |
|---|---|
| Комнаты (Студия / 1к / 2к / 3 и больше) | `types` (3 и больше = 3к, 4к, 5к) |
| Бюджет «До X», «X–Y», «Больше X» | `priceMax`, `priceMin..priceMax`, `priceMin` |
| B: район | `districts`; «Уралмаш, Эльмаш» и «Ботаника, Уктус» — по два района |
| C: «Заехать сразу» / «Свой ремонт (white box)» / «Не знаю» | `finish: clean / preclean / any` |
| Заезд «Как можно скорее» / «В течение года» / «Не важно» | `delivery: handed / withinYear / any` |
| Цель, способ оплаты, взнос, маткапитал | фильтра нет, только уходят в заявку |

Подсказка у вариантов комнат в A («Студия · от 3,0 млн») не вписывается руками: она считается из базы (`hint: "fromPrice"`).

Если район из ТЗ не находится через `normalizeDistrict`, не придумывай соответствие: напиши об этом в отчёте.

## 5. Подбор квартир из базы

### Нормализация данных

- `finish`: в базе встречаются «Чистовая отделка», «Чистовая», «Предчистовая отделка», «Предчистовая» и пустое значение (больше 40 % квартир). Приводим к `clean | preclean | unknown`. При фильтре `clean` или `preclean` квартиры с `unknown` не показываем, при `any` показываем.
- Срок сдачи: `project.delivery_date` в формате `ДД.ММ.ГГГГ`.
  - `handed` — дата в прошлом.
  - `withinYear` — сдан или сдаётся в ближайшие 12 месяцев.
  - В карточке: «дом сдан» или «сдача 2027».
- `type` уже нормализован («студия», «1к» и т. д.). Квартиры без цены или с ценой ниже 1,5 млн пропускаем как мусор в данных.

### Индекс

Серверная функция `getLandingIndex()` в `lib/cms/client.ts` или рядом. Она тянет все квартиры с полями `slug, type, area_m2, price_from, finish, floor_plan_url` и проектом (`slug, name, district, delivery_date`) и кешируется на час. Расширь существующий запрос или сделай отдельный, но без N+1 и с постраничной выборкой через `fetchAllPages`.

### Эндпоинт

`GET /api/lp/match?variant=…&type=…&a=<ответы>`. Ответ:

```json
{ "count": 75, "projects": 14, "relaxed": false,
  "cards": [{ "price": 4030000, "type": "студия", "area": 27.3, "project": "Астон.Движение",
              "delivery": "дом сдан", "finish": "предчистовая", "plan": "https://…", "payment": 19300 }] }
```

- Ответы принимаются только из белого списка индексов вариантов. Мусор отвечает `400`.
- `Cache-Control: public, s-maxage=600`.
- **Карточки:** 3 штуки, самая дешёвая квартира в каждом из трёх разных ЖК, по возрастанию цены.
- **Мало совпадений** (меньше 3 квартир): ослабляем по шагам, пока не наберётся 3.
  1. Снимаем фильтр по сроку.
  2. Снимаем фильтр по району.
  3. Поднимаем `priceMax` на 15 %.

  В ответе `relaxed: true`, заголовок результата становится «Точных совпадений мало — вот ближайшие варианты». **Экран «Нашли 0 квартир» не показываем никогда.**
- **Платёж:** `calcMonthlyPayment`, ставка семейной ипотеки из `getMortgageConfig()` (по label, как в `quiz-flow.tsx`), взнос 20 %, срок 30 лет (360 мес.). Это ровно то, что написано мелким текстом на странице: «семейная ипотека 6 %, взнос 20 %, 30 лет». Если ставка в конфиге поменяется, текст тоже должен браться из конфига, а не быть вписан руками.
- **Блок «Цены»** и H1 с «от N млн» (B: «от 4,5 млн») считаются этим же кодом при рендере страницы. Минимум по фильтру карточки округляется вниз до 0,1 млн. Цифры из ТЗ дизайна — примеры, не константы.

## 6. Квиз — оверлей

Клиентский компонент `components/lp/quiz-overlay.tsx`.

- **Открытие.** Квиз открывается любой кнопкой «Подобрать…» или «Начать…», карточкой цены и кнопкой в плавающей панели. Если квиз открыт с карточки цены, бюджет уже выбран и этот вопрос пропускается. Счётчик «Вопрос N из M» это учитывает.
- **Внешний вид.**
  - Мобильный: на весь экран, скролл страницы под ним заблокирован.
  - Десктоп: модальное окно 560 px.
  - Закрытие: крестик и Esc. Кнопка «Назад» в браузере тоже закрывает квиз, а не уводит со страницы: открытие пишет `history.pushState`.
- **Шаги.** Выбор ответа сразу ведёт к следующему вопросу (задержка как `ADVANCE_DELAY_MS` в `quiz-flow.tsx`), кнопки «Далее» нет. «← Назад» есть на всех вопросах, кроме первого.
- **Результат.** После 4-го вопроса — экран результата, данные из `/api/lp/match`.
  - Пока данные грузятся, показывается скелетон, не пустой экран.
  - Если сеть упала, текст «Не получилось посчитать — оставьте телефон, пришлю варианты сами» и сразу экран контактов.
- **Экран контактов.**
  - Переключатель Telegram / MAX / Звонок, по умолчанию Telegram.
  - Телефон с маской `+7 (___) ___-__-__`, валидные только 10 цифр после +7.
  - Чекбокс согласия: по умолчанию выключен, ссылка на `/privacy`.
  - Honeypot и `elapsedMs` как в `quiz-flow.tsx`.
  - Имя не спрашиваем.
- **Экран «спасибо».** Текст зависит от выбранного мессенджера:
  - Telegram: «Напишу в Telegram…»;
  - MAX: «Напишу в MAX…»;
  - Звонок: «Позвоню в течение 15 минут, с 9:00 до 21:00».

  Дальше рамка с бонусом из конфига и кнопка «Написать Яне сейчас» на `TELEGRAM_URL`. Памятки из бонусов — это то, что Яна присылает в мессенджере. Файлов на сайте нет.
- **Состояние.** Если закрыть квиз и открыть снова, он продолжается с того же места. После отправки заявки повторное открытие показывает «спасибо», а не новый квиз.
- **Подгрузка.** Код квиза грузится лениво (`next/dynamic`), но подгружается заранее в `requestIdleCallback` после загрузки страницы, чтобы первый клик открывал его мгновенно.

## 7. Остальные интерактивные элементы

- **Плавающая панель внизу (только мобильный).** Появляется, когда первый экран ушёл из вида (`IntersectionObserver`). Прячется, пока открыт квиз и пока в зоне видимости финальная форма.
- **Финальная форма** внизу страницы — та же форма контактов, что в квизе, общим компонентом. Заявка из неё уходит без ответов квиза, `quiz_answers: null`.
- **FAQ.** Аккордеон на `<details>/<summary>`, без JS.
- **Ссылки на телефон и Telegram** с целями Метрики (см. раздел 9).

## 8. Заявки: изменения в Strapi

**Схема `lead`:**

| Поле | Изменение |
|---|---|
| `name` | Становится необязательным. Контроллер требует имя для всех источников, кроме `landing`. |
| `lead_source` | В enum добавляется `landing`. |
| `messenger` | Новое поле, enum `telegram | max | call`. |
| `landing` | Новое поле, string: вариант и подвариант, например `kvartiry/1k`. |
| `utm` | Новое поле, json: `utm_source, utm_medium, utm_campaign, utm_content, utm_term, yclid`. Значения обрезать до 200 символов, ключи только из этого списка. |

Описания новых полей пишутся по-русски, как у существующих: их читают в админке.

**Контроллер** (`apps/cms/src/api/lead/controllers/lead.ts`): `lead_source = "landing"`, если пришло поле `landing`. Без него логика `quiz`/`viewing` остаётся как сейчас. Нормализация телефона и антиспам не меняются.

**Фронт.** `submitLead()` получает необязательные `landing`, `messenger`, `utm`. Кроме того:

- `source_path`: путь вместе с `type`, например `/lp/kvartiry?type=2k`;
- `source_title`: «Лендинг C · с отделкой»;
- `quiz_answers`: ответы текстом плюс `matched: { count, projects, relaxed }`.

UTM и `yclid` при первом заходе сохраняются в `sessionStorage` (в try/catch), чтобы пережить перезагрузку страницы.

**Уведомление Яне в Telegram (новое, сейчас его нет ни для каких заявок).**

- **Когда:** lifecycle `afterCreate` у `lead`, для всех источников, не только лендинга. Обещание на странице «напишу в течение 15 минут» без уведомления не выполнить.
- **Настройки:** токен бота и chat_id из env `LEAD_BOT_TOKEN`, `LEAD_BOT_CHAT_ID`. Если их нет, тихо пропускаем с одним предупреждением в лог.
- **Ошибки:** ошибка отправки не должна ронять создание заявки. Таймаут 5 с, без ретраев в запросе.
- **Текст:**
  - источник и вариант;
  - телефон как ссылка `tel:`;
  - мессенджер;
  - ответы квиза построчно;
  - сколько нашлось;
  - `utm_term`;
  - ссылка на заявку в админке.
- Бота и env на сервере заводит пользователь, ты только пишешь код и добавляешь переменные в `.env.example`.

## 10. Производительность и вёрстка

- Фото Яны через `next/image` с `priority` и правильным `sizes`. На мобильном фото сверху первого экрана, около 300 px, кадр по лицу.

- Без слайдеров, каруселей и видео.
- Кликабельные элементы не ниже 48 px. Контраст не ниже 4,5:1.

## 11. Заглушки: что не показывать в проде

- **Кейсы клиентов.** Пока в конфиге нет реальных, подблок кейсов **не рендерится**. Выдуманные истории на рекламной странице показывать нельзя. Остальной блок «Доверие» (сертификат, застройщики) рендерится.
- **ИП/ИНН в подвале.** Константа в `lib/site.ts`. Если она пустая, в dev выводится предупреждение в консоль, а в отчёте этот пункт помечается как блокер запуска.
- **C: стоимость доотделки за м².** Константа `FINISH_COST_PER_M2` (для предчистовой и черновой) с `TODO`. Пока не заполнена, вопрос «Бюджет вместе с ремонтом» фильтрует по цене квартиры без добавки.
