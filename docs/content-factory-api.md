# Content-factory API

Автопостинг статей на сайт — через REST API Strapi. Аутентификация: Bearer-токен `content-factory-publisher` (создаётся один раз в /admin → Settings → API Tokens, права: `article.create`, `article.update`).

## Публикация статьи

```
POST /api/articles?status=published
Authorization: Bearer <content-factory-publisher token>
Content-Type: application/json
```

```json
{
  "data": {
    "title": "Заголовок статьи",
    "slug": "unikalnyi-slug-stati",
    "excerpt": "Короткий тизер для карточки в списке.",
    "content": "# Заголовок\n\nАбзац с **жирным** и *курсивом*.\n\n## Подзаголовок\n\n| Программа | Ставка |\n| --- | --- |\n| Льготная | 6% |\n\n![Подпись к фото](https://example.com/photo.jpg)\n",
    "category": "Ипотека",
    "platform": "blog",
    "read_minutes": 6,
    "published_date": "2026-08-20",
    "hashtags": ["ипотека", "екатеринбург", "новостройки-2026"],
    "cover_url": "https://example.com/cover.jpg",
    "seo_title": "SEO-заголовок (опционально)",
    "seo_description": "SEO-описание (опционально)",
    "ai_meta": { "topic": "...", "key_idea": "...", "run_id": "...", "sources": [] }
  }
}
```

### Форматирование `content`

Поле — обычный Markdown (GFM), рендерится на сайте один в один. Поддерживается всё:

- Заголовки: `# H1` … `###### H6`
- Акценты: `**жирный**`, `*курсив*`, `` `код` ``
- Списки: `- пункт` (маркированный), `1. пункт` (нумерованный)
- Таблицы: стандартный синтаксис `| колонка | колонка |`
- Цитаты: `> текст`
- Ссылки: `[текст](https://...)`
- **Картинки по прямой ссылке**: `![подпись](https://...)` — грузить в Strapi Media Library не нужно, картинка сразу отображается на сайте по URL. Так контент-завод вставляет свои сгенерированные/подобранные изображения без лишнего шага загрузки.

### Обложка статьи — `cover_url`

Передайте `cover_url` вместо (или вместе с) `content` для автоматической загрузки обложки — сервер сам скачает картинку по ссылке и прикрепит как обложку статьи, без ручной загрузки через Media Library. В отличие от загрузки по ссылке в самой админке (браузер, ограничена CORS-политикой источника), этот путь — сервер-сервер, работает с любым хостингом картинок независимо от CORS.

- `cover_url` — обычная прямая ссылка на изображение (jpg/png/webp/gif).
- Если ссылка недоступна или отдаёт не изображение — весь запрос вернёт `400` с понятным текстом ошибки (`cover_url вернул HTTP 404`, `cover_url — не изображение`), статья не будет создана — так пайплайн сразу увидит проблему вместо статьи без обложки.
- При повторной публикации по тому же `slug` новый `cover_url` заменит обложку.
- В ответе поле `cover_url` не возвращается — вместо него у статьи появляется обычная связь `cover` (как при ручной загрузке файла).

## Идемпотентность

Эндпоинт идемпотентен по `slug`: повторный `POST` с уже существующим `slug` **обновляет** статью, а не создаёт дубликат. Ответ на такой повторный запрос содержит `meta.idempotent: "updated-existing-slug"`.

Чтобы перевыпустить статью с тем же контентом (например, после исправления), просто отправьте `POST` с тем же `slug` и новыми данными — старая запись обновится по её `documentId`, ссылка на сайте (`/blog/<slug>`) не изменится.

## Черновик вместо публикации

Уберите `?status=published` из запроса — статья создастся как черновик и не будет видна на сайте, пока её не опубликуют вручную в /admin (Content Manager → Article → Publish).

## Лимиты

- 30 запросов в минуту на один Bearer-токен на запись (`POST`/`PUT`/`DELETE` на `/api/articles`). Превышение — `429 Too Many Requests`.
- Чтение (`GET`) не лимитируется этим правилом.

## curl-пример

```bash
curl -X POST "https://<домен-сайта>/api/articles?status=published" \
  -H "Authorization: Bearer <content-factory-publisher token>" \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "title": "IT-ипотека в 2026: что изменилось",
      "slug": "it-ipoteka-2026-izmeneniya",
      "excerpt": "Кратко о новых условиях программы.",
      "content": "## Что нового\n\nТекст статьи.",
      "category": "Ипотека",
      "read_minutes": 5,
      "published_date": "2026-08-20"
    }
  }'
```

## Поля

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `title` | string | да | Заголовок |
| `slug` | string | да | Уникальный слаг, ключ идемпотентности |
| `content` | string (markdown) | да | Текст статьи: `##` заголовки, `**bold**`, `- списки` |
| `excerpt` | string | нет | Тизер для карточки в списке |
| `category` | string | нет | Категория для фильтра в блоге (напр. "Ипотека", "Маткапитал") |
| `read_minutes` | integer | нет | Время чтения в минутах |
| `published_date` | date (`YYYY-MM-DD`) | да | Редакторская дата публикации (используется для сортировки и отображения — отдельно от служебного поля Strapi `publishedAt`) |
| `platform` | enum | нет | `blog` \| `vc` \| `dzen` \| `tenchat` \| `telegram` \| `max` (по умолчанию `blog`) |
| `hashtags` | string[] | нет | Ключевые слова для SEO и ИИ-поиска (GEO), не показываются читателю напрямую — массив строк |
| `cover_url` | string (URL) | нет | Прямая ссылка на картинку обложки — сервер скачает и прикрепит сам, см. раздел выше |
| `seo_title` / `seo_description` | string | нет | Переопределяют `<title>`/`<meta description>` страницы статьи |
| `ai_meta` | json | нет | Служебные метаданные генерации: `{ topic, key_idea, run_id, sources[] }` |
| `views` | integer | — | Только для чтения, счётчик просмотров сайта. Не передавайте это поле при публикации — оно инкрементируется отдельным публичным эндпоинтом `POST /api/articles/:documentId/view` при открытии статьи на сайте. |

Автопостинг на внешние площадки (Telegram, VC, Dzen, TenChat, MAX) выполняется на стороне контент-завода — сайт предоставляет только этот API как источник контента.

## Комментарии читателей

Комментарии — отдельный content-type (`api::comment.comment`), не связанный с токеном контент-завода. Читатели оставляют их прямо на сайте под статьёй; каждый новый комментарий приходит со статусом «На модерации» и становится виден на сайте только после одобрения в /admin (Content Manager → «Комментарии к статьям»). Автопостингу эта сущность не нужна.
